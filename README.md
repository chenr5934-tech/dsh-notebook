# dsh-notebook

让模型拥有自己的经验本：**开工前读，收工后写**。每个项目一份，可开关，带可视化管理界面。

针对 DeepSeek Harness Desktop（Electron，内嵌 dsh-web-app）。

## 它解决什么

模型每次会话都失忆，同样的坑会反复踩。这个插件把"坑"沉淀成两份文件：

| 文件 | 内容 | 作用范围 |
|---|---|---|
| `agent.md` | 通用经验：跨项目成立的失败模式 | 所有项目共用一份真身 |
| `project_agent.md` | 项目经验：本项目的不变量、判定手段、高危区 | 单项目 |

两份文件由 dsh 的 `agent-instructions` 加载器注入，模型在开工前就能看到。

`project_agent.md` 的每一条前面标着 `（2026-11-18 10:37）`，是这条经验最后改动的时间。时间取三种来源：新写或内容改过的取保存那一刻；内容一字未改的保留旧时间，所以连点几次「保存并同步」不会把全部条目刷成现在；早于这个功能就存在的条目取 `notebook.json` 的文件修改时间，且只在读取时补上，不写回真身。精确到分钟，同一天连着写好几条也能分出先后；缺时间的条目写成「时间未知」，不留空括号。界面上同样的时间显示在每张项目卡的标题右侧。

## 设计要点

- **不重造注入器。** dsh 已自带 `@deepseek-ai/dsh-agent-instructions`（去重、增量更新、压缩后重建、转义、字节预算都已处理）。本插件只负责"写什么"，注入交给它。
- **真身与投影分离。** 内容真身是 JSON（`$DSH_HOME/notebook/universal.json`、`<项目>/.dsh-notebook/notebook.json`）；markdown 只是投影，可随时重建。
- **受管区块。** 只改 `<!-- dsh-notebook:begin -->` / `end` 之间，区块外的用户手写内容一字不碰。
- **关闭即清空。** 停用时摘掉区块；纯投影文件直接删除。日常对话不产生任何注入。
- **注入面只放索引。** 候选条目只进表格，`确立` 的条目才带全文进上下文——10 条经验约占 39 行。
- **项目名由模型自取。** 每份项目本有 `project` 字段，模型按项目内容自行命名，写进标题首行（`# 项目经验本：<名字>`），也用于界面里的项目列表——文件夹名未必能说明项目是干什么的。

## 安装

**从 GitHub 装**（推荐）：仓库 Releases 里有 `dsh-notebook-<版本>.zip`，解开后让 dsh 指向解开的目录即可：

```
plugin_manager  action=install_bundle  target=<解开后的目录>
```

想自己改代码就克隆仓库，`target` 指向克隆下来的目录：

```
git clone https://github.com/chenr5934-tech/dsh-notebook.git
plugin_manager  action=install_bundle  target=<克隆目录>
```

不解压也行——Release 里的 `.tgz` 可以直接当 `target`，pnpm 会把它解开成实体目录。

`install_bundle` 会完成 pnpm 链接、`dependencies` 与 `dsh.profile.bundles` 两处登记，并把 `cordis.patch.yml` 叠进层栈。返回里 `application: "applied"` 才算生效；`restart-required` 表示要重启 dsh 才能加载新模块代次。

**给别人装**：把 `.tgz` 或解开的目录发过去，`target` 指向其一即可，对方不需要这份源码。分发说明与手动安装步骤见外发包里的 `README.md`。

装完重启 dsh，然后四步验证：

1. 页面对得上：`/notebook` 命令（见下）会打印实测出来的界面地址；宿主决定端口，插件不再假设 43120
2. 开关写盘：页面里打开开关后，项目根的 `agent.md`、`project_agent.md` 出现受管区块
3. 模型读得到：新会话里问一句"你的经验本里有什么"，能答出条目
4. 到点提醒：把频率改成每轮，聊满一轮后模型会收到 `<system-reminder>`

手写 profile、在 profile 里跑 pnpm、在 `$DSH_HOME` 下建包都不必做——真要手写，见 **[docs/INSTALL.md](docs/INSTALL.md)**（含备份、排查表、回滚）。
上架与打包要求：**[docs/RELEASE.md](docs/RELEASE.md)**。

> 装之前注意：本插件会替换 `agent-instructions` 的 `instructionFileCandidates`，并在项目根生成 `agent.md` / `project_agent.md`（仅在该项目开启后）。若用户层 patch 也写过这个数组，以用户层为准，两项得自己补进去。

## 使用

**界面**：侧栏「备忘录」一行点开即是（`order 40`，在「技能中心」之后）。面板与独立页共用同一份界面：面板用同源 iframe 装它，所以两边永远不会漂移。独立页地址是 `<宿主 origin>/dsh-notebook/?project=<项目绝对路径>`，origin 由宿主决定，跑一次 `/notebook` 就打印出来（实测是 `http://127.0.0.1:<端口>`）。

**第一次用**：右下角会浮出一张「三分钟上手」卡片，五条要点覆盖定项目根、选项目、开关、记条目、让模型自己维护。它不是模态窗——卡片浮在页面上，底下的控件照样能点，可以边看边做。勾上「以后不再提醒」再点「知道了」就不再出现；不勾则下次打开还会弹。随时点页脚「使用说明」能把卡片叫回来，插件简介页里也有一份完整的文字教程。

然后要在右上角「项目根」里填你放项目的目录（例如 `D:\dsh工作区\PROJECTS-项目`），回车即存到 `$DSH_HOME/notebook/config.json`，下次打开还在。填完左边列表会列出该目录下的项目，选一个即可；也可以跳过项目根，直接在「项目绝对路径」里填完整路径。

项目根留空时列表是空的，界面会提示先填——不会拿宿主进程的工作目录来凑数（那是 dsh 自己的 profile 目录，列出来全是无关目录）。

布局：
- **左栏**：归属本项目的会话历史（开启之后产生的），显示标题、时间、轮次；点开可读全文
- **右栏**：两列并排——「通用经验本」与「项目经验本」，逐条可编辑
- **底栏**：更新频率（每 1/2/3/5/10 轮）、自审查、保存并同步

能做的事：
- 开关该项目的经验本
- 增删改任意条目（通用：症状/根因/识别/防御/边界；项目：项目结构/不变量/判定/高危区/本地约定）
- 给项目起名（模型按项目内容自取，用于区分不同项目）
- **自审查**：生成一份审查提示（先点名三条最该删的，再谈新增）
- 调更新频率：默认每 3 轮，项目后期建议改成每轮

**怎么防止写成一堆废话**（不是靠模型自觉，三层挡）：

1. **准入四问**（写进提醒）：可复现（说得出触发条件）、非显然（不看就会踩）、有代价（真报过错／白跑过）、可执行（能落成「下次遇到 X 就做 Y」）。四问全过才写，卡住任一问就不写。提醒里另附反例黑名单：流水账、一次性状态、没验证的猜测、普适正确的空话、已在 `AGENTS.md` 里的。
2. **渲染层不给废话留位置**：同标题只留 `updatedAt` 最新那条；只有标题没结论的降级成一行 `（只有标题，没有结论）`；标了 `established` 但四段全空的不进全文区（只在索引表出现）。重复和空洞因此没有收益。
3. **数量闸**：项目本到 40 条时提醒改口径为「本轮不要新增，先挑三条最该删的」。

**命令**：`/notebook status | on | off | every <n> | review [项目路径]`

**模型侧**：不需要专用工具。模型用自己的读写能力维护这两个文件即可——文件本身就是"怎么用"的说明。项目本的「项目结构」区块用来固定"什么该放哪"，避免新会话把文件乱塞。

## 开发

```bash
npm run check   # node --check 四个 lib 文件 + client.js
npm test        # 四套：manifest 契约（含客户端注册）/ 渲染与区块 / 提醒判定 / 路由+命令+提醒的端到端 harness
node scripts/seed.mjs   # 重建本项目的投影
```

`test/manifest.mjs` 校验 bundle 契约本身：`dsh.bundle.patch`、`exports['./locale/*.json']` 与 `exports['./icon']`、图标尺寸与内容、两份 locale 的 `meta.title`/`meta.description`、`files` 白名单、详情页的 640×300 单图与"无 text/script/foreignObject"禁令。它不跑 dsh，纯文本校验，改 manifest 后先跑它。

无构建步骤：纯 ESM + 手写 HTML，不引入 bundler。

## 已知限制

- **已在 dsh 进程内验证**：`install_bundle` 返回 `applied`；`/dsh-notebook/` 与 `api/state|sync|review` 在运行中的宿主返回 200 / 真实数据；`/dsh-notebook/nope` 返回 404，证明走的是 exact 页面路由
- **提醒已接通**：订阅 `agent/pre-step`，用宿主给的 `payload.turn` 判到点，往 `agent.inbox.prepend('next-step', …)` 排一条 `source.plugin = dsh-notebook` 的消息，并在排入前顺手同步一次投影；同一形态的提醒只排一条。提醒文本与"真正入队后模型是否照做"仍取决于会话本身
- 会话归属靠 `cwd` 或首条消息里的项目路径匹配——dsh 按启动目录分组会话，不是按项目。项目根下还有一层容器目录（如 `PROJECTS-项目/<项目>`）时，插件按"浅层与深层两个候选、取磁盘上存在的那个"来认
- 会话列表要解压全部会话文件，160 个会话约 0.6 秒（只读头部时）；点开单条才解全文
- 侧栏面板是 iframe 外壳 + 同一份界面，不是重写成 React 组件。好处是面板与独立页永不漂移，代价是面板内不能复用宿主的主题上下文，深浅色由界面自己维护
- 单用户、单机；无云端同步
